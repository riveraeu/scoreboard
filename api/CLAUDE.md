# api/ — module map

Loads when working under `api/`. Root `CLAUDE.md` holds the always-on doctrine (qualification, capture window, category gate, Key Gotchas); this file is the per-module map. Route contracts live in the `api-routes` skill.

### API: `api/[...path].js` (router) + `api/lib/handlers/*.js` (routes) + `api/lib/*.js` (modules)

`api/[...path].js` is a thin router: CORS preflight, `makeCache`, dispatch to one handler per route family.

- `shadow.js` — `/api/shadow-snapshot`, `/api/shadow-resolver`, `/api/shadow-pregame-snap`, `/api/shadow-report`, `/api/{polymarket,sportsbook}-deltas`, `/api/polymarket-scan`, `/api/routine-note`, `/api/kalshi-dryrun-check`. `shadow-report` fields, `makerBoard` is the only one the frontend reads — the rest are for the (non-UI) morning report: **`?makerDay=YYYY-MM-DD`** — single-day V1 maker attribution (`bySport`/`byBand`/`topTickers`/`ungraded`); `weightedAsk`/`weightedSideWon` are contract-weighted because that's the only pair satisfying the seller's identity `pnlPerContract = weightedAsk − 100·weightedSideWon`, and don't reconcile against the unweighted board fields sitting alongside them; graded-only. **`byCategoryBand`** — a sport×band cross-tab (the `bySport`/`byBand` marginals can hide a hit the cross-tab catches); returns **before** the report cache read, so nothing above it can assume the full report ran. **`dataFreshness`** — is the heatmap current through last night (`makerTableCurrent`, `daysBehind`, a `diagnosis` distinguishing *fills detected but not graded* from *nothing ran*). **`dataFreshness.quotePass`** reads the `maker:quotepass:{date}` KV hash (see `maker.js` `quotePassTelemetryCommands`) so `diagnosis` can name the failing subsystem instead of listing candidates; absent key (>48h, pre-ship run) falls back to the old generic wording, honestly. **`discovery`** — the Kalshi series-scan vet queue (`toVet` = `status IN (new,shortlisted) AND screen='REAL_BOOK'`, `perGame` flags bare-prefix futures vs GAME-suffix per-game markets); `screen=REAL_BOOK` is evidence to VET, never grounds to build (GAME-suffix/ESPN-slug/team-abbr cross-check are still human work). **`discovery.polymarket`** — sibling lane from `polymarket_sports_seen`, own nested try/catch (a missing Poly table can't blank the Kalshi list); per-LEAGUE (Gamma slug), not per-market-family, so it's not row-joined to the Kalshi list. **`uiHealth`** — asserts the landing page's rendered payload is present and complete (orthogonal to `dataFreshness`: an on-time report can still ship a blank/degenerate board). Pure `computeUiHealth(makerBoard, preregistrations)` over the in-memory payload, so it can never disagree with what ships; validates both `CategoryBandHeatmap`'s render-critical fields and `PreregTracker`'s. **`robustCandidates`** — the heatmap-robustness TRIPWIRE, NOT read by the frontend. The category×band grid is mostly noise (~1/40 cells clear a 95% CI by chance), so `computeRobustCandidates(makerBoard)` (pure, tested) requires a cell cross a strict structural bar (`ROBUST_BAR {minDays:8, minFills:50, maxTopDayShare:0.35}`, day-clustered CI excluding zero on the positive side) before it's even a pre-registration CANDIDATE — never a bet or ranked shortlist, and robustness alone is not sufficient (a past candidate cleared this bar clean in-sample and still inverted forward). The day-clustered CI narrows as days accumulate, so eventually most of the board crosses `ciLo > 0` on a price-monotone book — **read the asymmetry between `candidates` and `negatives`, never `count` alone** (a negative-heavy read is the band-ladder artifact, `docs/MAKER_LADDER_ARTIFACT.md`, not new signal). Sorted by cell name, never by `perContract` (that would be a ranked shortlist). Its companion anomaly flag (`ladderAnomalies`, `api/lib/maker-stats.js`, pure+tested) tests each cell against the CATEGORY's own fitted price→outcome curve (leave-one-out isotonic fit over band midpoints, flagged on a combined-SE residual ≥ `LADDER_BAR.minResidual` 0.15) rather than a naive price-equals-frequency null — the naive null is falsified by construction on any ladder, so it used to flag ladder ENDS, not bugs. A category-level check runs first (a wholesale side-flip inverts every band together, invisible per-cell). **Standing result: the per-cell test has produced flags across two tuning generations and zero confirmed pipeline defects** — trust the category-level inversion check for the actual bug class; treat per-cell flags as noisy-ladder candidates to sanity-check, not integrity findings. **`venueVig`** — cross-venue Kalshi-vs-Poly favorite-ask VIG per category×band (`vig = avg captured ask − realized win rate`), the data behind `MakerBoardPage`'s `[Kalshi|Polymarket|Δ]` toggle. Computed identically on both venues from capture+resolution alone (no fills, no model) — Kalshi category derives from the market's own series prefix (`venueCategoryFromKalshiTicker`); the SQL CASE, the JS classifier, and the Poly-side category filter are all built from the SAME `KALSHI_VENUE_CATEGORY_PREFIXES` map so they can't drift apart (a hand-written fourth copy already did once). `computeVenueVig` pure+tested. **A divergence MONITOR, not a ranking** (expected ≈0; a lit Δ cell is a prompt to pre-register a mechanism, never a bet); degrades to a placeholder rather than blanking the page. **`polymarketTracking`** — the Poly-instrument health block (`capture` rows/days/recentBySport, `resolution` graded/voided/pending, a `vig` summary off `venueVig` incl. `topDivergences`), same divergence-monitor doctrine.

- `maker-stats.js` — **contract-weighted maker PnL + CI** (2026-07-25). `contractWeightedPnl()` (pure, from six plain sums) + `weightedPnlSumsSql`/`weightedPnlFromRow`; surfaces as `makerBoard.fills.weighted` and `makerBoard.live.weighted`. Exists because both boards' headline `avgPnlCents` is an UNWEIGHTED per-FILL mean — a 1-contract and a 500-contract fill count equally, but capital earns the weighted number. **The trap it avoids**: weighting by treating each CONTRACT as an observation is wrong, because all contracts in one fill share a single outcome (perfectly correlated) — that inflates effective n by mean fill size (~6.6× on V1's book) and shrinks the CI ~2.6×, enough to arm real money on noise. The fill is the independent unit, so the weighted mean is a **ratio estimator** with a delta-method variance (`Var(R) ≈ (n/(n−1))·Σ[cᵢ(pᵢ−R)]²/(Σcᵢ)²`), pinned by a test proving it collapses to the textbook `s²/n` when all weights are 1. **`dayClusteredPnl()` (2026-07-26) — the interval to actually act on**, surfaced as `makerBoard.{fills,live}.dayClustered`. Same ratio estimator with the **DAY as the cluster**: `weighted` fixed correlation WITHIN a fill, this fixes correlation ACROSS fills sharing a day (V1 sells favorites, so a day's PnL is one bet on whether favorites underperformed that slate — hundreds of fills resolve off a few dozen correlated games). Not a small correction: on 2026-07-26 the same data gave `weighted` [+0.70, +2.81] (criterion satisfied) vs `dayClustered` **[−3.00, +6.47]** — point estimate unmoved (+1.76 → +1.73), interval ~4.5× wider and crossing zero, because +$1,865 of the +$1,066 total came from **two** of seven days. `armCriterion` now carries `need` (historical fill-level bar), `needClustered` (`dayClustered.loCI > 0`), `minDays` 14, and a computed `met` combining all three — read `met`, never `need` alone. **The fill-level field was renamed `pnlLoCI_fillLevel_SUPERSEDED` at all 7 emit sites (2026-07-28)** after it rendered a false green on the landing page's arm tile (t=3.56, P(edge>0)~100%) the morning V2 was shelved — the fourth false green from that statistic. The verbose name is the guard: it cannot be grabbed by autocomplete or a grep for `pnlLoCI`.
- `maker-prereg.js` — **pre-registered maker forward tests** (2026-07-30). `PREREG_CELLS` registry + pure `evaluatePrereg(spec, result, nowPT)`; surfaces as `preregistrations[]` / `PreregTracker`. **The ONLY doctrine-sanctioned "when will we know" surface** — a *calendar checkpoint* fixed BEFORE the forward window opens, never a data-extrapolated ETA on a bright cell (that would re-slice the same in-sample days the REENTRY doctrine has repeatedly failed on).
