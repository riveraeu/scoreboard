# api/ — module map

Loads when working under `api/`. Root `CLAUDE.md` holds the always-on doctrine (qualification, capture window, category gate, Key Gotchas); this file is the per-module map. Route contracts live in the `api-routes` skill.

### API: `api/[...path].js` (router) + `api/lib/handlers/*.js` (routes) + `api/lib/*.js` (modules)

`api/[...path].js` is a thin router: CORS preflight, `makeCache`, dispatch to one handler per route family.

- `maker-stats.js` — **contract-weighted maker PnL + CI** (2026-07-25). `contractWeightedPnl()` (pure, from six plain sums) + `weightedPnlSumsSql`/`weightedPnlFromRow`; surfaces as `makerBoard.fills.weighted` and `makerBoard.live.weighted`. Exists because both boards' headline `avgPnlCents` is an UNWEIGHTED per-FILL mean — a 1-contract and a 500-contract fill count equally, but capital earns the weighted number. **The trap it avoids**: weighting by treating each CONTRACT as an observation is wrong, because all contracts in one fill share a single outcome (perfectly correlated) — that inflates effective n by mean fill size (~6.6× on V1's book) and shrinks the CI ~2.6×, enough to arm real money on noise. The fill is the independent unit, so the weighted mean is a **ratio estimator** with a delta-method variance (`Var(R) ≈ (n/(n−1))·Σ[cᵢ(pᵢ−R)]²/(Σcᵢ)²`), pinned by a test proving it collapses to the textbook `s²/n` when all weights are 1. **`dayClusteredPnl()` (2026-07-26) — the interval to actually act on**, surfaced as `makerBoard.{fills,live}.dayClustered`. Same ratio estimator with the **DAY as the cluster**: `weighted` fixed correlation WITHIN a fill, this fixes correlation ACROSS fills sharing a day (V1 sells favorites, so a day's PnL is one bet on whether favorites underperformed that slate — hundreds of fills resolve off a few dozen correlated games). Not a small correction: on 2026-07-26 the same data gave `weighted` [+0.70, +2.81] (criterion satisfied) vs `dayClustered` **[−3.00, +6.47]** — point estimate unmoved (+1.76 → +1.73), interval ~4.5× wider and crossing zero, because +$1,865 of the +$1,066 total came from **two** of seven days. `armCriterion` now carries `need` (historical fill-level bar), `needClustered` (`dayClustered.loCI > 0`), `minDays` 14, and a computed `met` combining all three — read `met`, never `need` alone. **The fill-level field was renamed `pnlLoCI_fillLevel_SUPERSEDED` at all 7 emit sites (2026-07-28)** after it rendered a false green on the landing page's arm tile (t=3.56, P(edge>0)~100%) the morning V2 was shelved — the fourth false green from that statistic. The verbose name is the guard: it cannot be grabbed by autocomplete or a grep for `pnlLoCI`.
